# 第八阶段：首页、详情与分类页面审查

## 第一轮：分类列表请求隔离与取消

### 审查范围
- `ui/page/HomeViewModel.kt`
- `ui/page/PartitionListViewModel.kt`
- `sourcedata/SourceViewModel.kt`
- `sourcedata/ListLoader.kt`
- `sourcedata/SourceResultParser.kt`
- `ui/DetailViewModel.kt`
- `ui/DetailScreen.kt`
- `skill/avbox-mobile-ui-spec.md` §4.1

### 发现
- 首页分类和分类二级页都允许在同一个 `SourceViewModel` 上替换等待中的回调，但旧分类请求此前没有被明确取消。
- 例如用户快速更改筛选条件或重试时，旧请求可能晚于新请求返回；由于列表结果通道本身不携带请求标识，旧结果可能被当前回调误认为新请求结果。
- 详情页已有 `detailToken` 和 `DetailResponseGuard`，本轮确认详情响应过期保护已存在，不重复造轮子。

### 修复
- `SourceViewModel.getList` 每次启动列表请求时先取消前一请求链，并为本次请求建立独立的结果通道。
- 只有当前请求代际的结果才会转发到公开的 `listResult`，旧请求的迟到结果无法进入首页/分类页观察者。
- 新增 `cancelList`，在首页分类 Loader 和分类二级页 Loader 释放时取消底层列表请求。
- 保留独立的首页推荐列表 Loader，避免分类列表请求隔离影响首页推荐获取。
- 新增 `SourceListRequestGateTest`，覆盖当前请求通过、旧请求失效。

## 第二轮：同源刷新时分类元数据旧响应保护
### 发现
- 首页分类元数据请求（分类/筛选定义/推荐列表）此前复用单一 `SortLoader` 和单一 `sortResult` 通道。
- 同一订阅源快速刷新或重试时，旧请求可能晚于新请求完成；仅比较 `sourceKey` 无法区分同一源的不同请求。
- 首页 ViewModel 被清理时，之前没有主动取消排序/推荐元数据请求。

### 修复
- 每次 `getSort` 建立独立结果通道和请求代际，旧请求即使迟到也不能转发到当前页面。
- 每次元数据请求取消上一条请求链。
- 推荐列表 Loader 也按当前元数据请求单独创建，避免旧请求与新请求共享结果通道。
- 首页 ViewModel 清理时取消排序和推荐请求，并取消看门狗。
- 扩展请求门禁单测，覆盖排序元数据请求代际。

## 第四轮：首页请求超时隔离
### 发现
- 首页原先使用单一 `watchdogJob`，每个分类列表请求启动时都会重置它；并发分类请求互相延长等待时间，不能满足每个请求独立 20 秒超时的要求。
- 如果超时只改变 UI 状态而不取消底层请求，迟到结果仍可能回填；同一分类随后重试时，旧请求的超时也不能误取消新请求。

### 调整
- 分类元数据请求使用独立 `sortWatchdogJob`，以 `loadGeneration` 区分换源/刷新代际；超时取消排序与推荐元数据请求，置失败状态并开放重试。
- 自动重试和空结果延迟重试重新启动 20 秒计时，避免把两次独立请求合并成一个时间窗口。
- 每个分类列表请求在取得 `loadSemaphore` 许可后独立执行 20 秒超时，不受其他分类请求影响。
- `PartitionLoader` 为每次请求分配 ID；超时只能取消仍属于该 ID 的 pending 请求，避免旧超时处理释放/取消后来启动的新请求。
- 首屏请求超时标记对应分类为 Error；分页请求超时保留已有列表内容并提示，不将整个分类清空。

## 第五轮：分类二级页超时、错误态与分页恢复
### 发现
- `PartitionListViewModel` 原本没有 Error 状态；首屏接口返回 null 会被误判为空列表。
- 二级页分页请求没有独立超时与可见恢复入口；分页失败后用户可能无法再次触发预加载。
- 分类导航/筛选重载后，旧请求存在迟到回写新页面状态的风险。

### 调整
- 首屏请求独立 20 秒超时；接口失败/超时进入错误态，提供重试按钮。
- 分页请求独立 20 秒超时；保留已加载视频，显示加载进度，失败后在网格底部提供重试入口。
- 请求捕获当前导航层级与 Loader 实例；只有仍属于当前页面的请求才允许更新 UI。
- UI 规范同步明确二级分类页的首屏错误和分页错误恢复方式。

## 第六轮：分页请求代际保护与详情页大屏布局
### 发现
- 分类二级页 Loader 虽然有超时取消，但取消动作未绑定到具体请求；超时与重试交错时，旧请求的取消可能触及新请求。
- 详情页内容列表在平板横屏下直接占满整个屏幕宽度，线路、选集、相关推荐等区域过宽，阅读视线跨度较大。

### 调整
- 为分类二级页 Loader 的每次请求分配递增 ID；只有 ID 与当前 pending 请求匹配时才允许取消。结果交付、取消、释放都会清除 pending ID。
- 详情页内容流最大宽度限制为 1200dp，并在宽屏中居中；外围 Hero 背景仍可铺满屏幕，不改变手机端布局。
